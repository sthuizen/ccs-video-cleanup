## Approved audio and playback

DeepFilterNet3 v0.5.6 runs locally with `-D -a 20`. Speech is phase-checked before mono conversion; opposed stereo must never be blindly summed. The subsequent FFmpeg chain is:

```text
highpass=f=75,lowpass=f=10000,afftdn=nf=-40:nr=8:tn=1:gs=8,agate=threshold=0.004:ratio=1.5:range=0.5:attack=10:release=300:knee=4:detection=rms
```

Constant gain targets -20 LUFS, limits gain to +18 dB and peaks to -2 dBFS with limiter makeup disabled. Context and delay correction preserve timing. The five-second intro is silent and final audio is encoded once from PCM. Finished videos and browser previews contain no inferred chapter labels. These choices match the approved Linux profile; native Windows/Linux executable hashes differ intentionally and are checked separately. See [audio research](../AUDIO_RESEARCH.md) and [detection evidence](../DETECTION_VALIDATION.md).

## Linux validation

The source suite passes all 51 Python tests and four Deno interface checks. Installed 1.3.0 packages were tested in Ubuntu 24.04 (Python 3.12) and Debian 13 (Python 3.13) root filesystems. Distribution dependencies were installed through APT; user setup downloaded specialist tools and cached models separately. Each installed environment passes the 51-test suite, including synthetic full rendering, opposed-stereo handling, speech enhancement, chapterless playback and audio/preview timing. Offline Whisper model loading and real RapidOCR initialization also pass.

These Linux environments run through proot on the host kernel. They verify package installation, user setup and processing, but do not establish every distro desktop/systemd login integration. The original laptop's existing desktop service and videos remain in place. The `.deb` does not bundle the church logo: supply the separately provided private release logo using the documented setup option.

## Windows validation

Testing uses actual Microsoft Windows x64 evaluation guests under QEMU/KVM, rather than assuming Linux tests establish Windows support. Windows 10 is 22H2 build 19045; Windows 11 is 24H2 build 26100. Both use embedded CPython 3.13.16 and independently downloaded pinned dependencies. No church recordings or personal browser credentials were copied into the guests.

Fresh Windows 11 user setup and Windows 10 upgrade setup succeeded. Real OCR recognized the synthetic church title card; offline speech recognition identified Romans chapter two, verses one to sixteen in generated test speech. Both systems completed a synthetic opposed-stereo video render using the native enhancer and approved 20 dB cap, with full decode validation, mono output, chapterless master/preview, Unicode paths, logo/health/jobs HTTP checks, repeat setup reuse, duplicate launch and refusal to shut down during processing.

A Windows 11 upgrade initially encountered inaccessible files in the old private Python cache. Setup now renames that cache before rebuilding it, retains jobs/models, and removes the old cache only when its permissions allow it. If cleanup cannot remove it, a `python-packages.previous-*` folder remains and setup explains this. The final installer successfully repaired the affected guest without changing ACLs or discarding user jobs/models.

The exact final installer passed all 51 Python regression tests (no skipped tests) and four Deno interface checks on both Windows versions. Its guest-side SHA-256 matched the release artifact on both systems. The final functional verifier also passed on both versions after the Windows 11 cache repair. A lab-only second data folder initially occupied port 8765; that test instance was closed and verification repeated successfully.

Final regression and artifact-integrity results are recorded in the accompanying [evidence](v1.3.0). The first Windows test run exposed POSIX-only test assumptions; the tests were corrected to use Windows executable names and avoid asserting Unix permission bits on NTFS.

## Scope and operation

The updated passage and boundary heuristics are included, but irregular services still need operator review. The built-in player and manual start/end controls remain the reliable fallback. Audio enhancement can retain speech-like crowd noise and reverberation; this release does not promise perfect source separation.

Windows first setup needs internet access; processing and cached speech/OCR inference run locally. Windows installer signing/reputation remains unchanged: the installer is unsigned. Live authenticated Windows YouTube downloading was not revalidated for this release; the earlier lab encountered rate limiting/sign-in verification. Use the documented Firefox option when required. Production-length Windows performance and every Windows edition/CPU were not exhaustively tested.

Both installers, checksums, separately supplied church logo, source tag and this record are preserved in the private GitHub release. Earlier releases remain available unchanged.
