## Evidence and limits

Machine-readable evidence is in [the Windows evidence folder](windows): functional inference reports, rendering validation, regression/UI test output, installer retention checks, CLI locking checks, fresh setup and synthetic intro images. [The reproduction guide](../WINDOWS_TESTING.md) explains the lab and commands. The final source tag includes these post-build records; they are not embedded into the application installer.

A live Windows downloader metadata request for the authorized public service reached YouTube but returned HTTP 429 and sign-in verification. **A successful authenticated Windows YouTube download was not verified in this lab.** The downloader module and Deno run natively; bitrate/format choice and access-error behavior passed their tests. Operators can use their own signed-in Firefox session when YouTube requests verification. No personal credentials were used to bypass the lab's network restriction, and the request was not repeatedly retried. See [the captured network result](windows/windows11-live-downloader.json).

These checks establish functionality on the listed Windows evaluation builds and modern x64 CPU virtualization. Other Windows editions/builds, older CPUs, ARM/32-bit PCs, corporate security policies and production-length Windows performance were not exhaustively tested. The operator recommendation remains a modern Intel/AMD x64 PC with 8 GB RAM and adequate video storage.

The installer is unsigned. Internet-download SmartScreen reputation is not established by a lab download; Windows may show an unknown-publisher/SmartScreen prompt. The Microsoft prerequisite itself was publisher-signature checked. First setup needs internet access; cached speech/OCR inference is local. No public redistribution clearance or new application licence is implied by these technical tests. See [rights](../../RIGHTS.md).
